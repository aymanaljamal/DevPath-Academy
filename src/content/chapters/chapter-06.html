React Hooks

6.1 Introduction to React Hooks

Simple Explanation

Hooks are functions that let you "hook into" React state and lifecycle features from functional components. Before Hooks, you could only use state and lifecycle methods in class components. Hooks were introduced in React 16.8 to make functional components just as powerful as class components.

Think of Hooks as special tools in your React toolbox. Each hook serves a specific purpose - some manage state, others handle side effects, and others optimize performance. You can even create your own custom hooks to reuse logic across components.

Technical Explanation

Hooks are JavaScript functions that allow you to use React features without writing classes. They provide a more direct API to React concepts like state, lifecycle, context, and refs. Hooks follow two main rules: 1. Only call hooks at the top level (not inside loops, conditions, or nested functions) 2. Only call hooks from React functions (functional components or custom hooks)

React provides built-in hooks for common use cases and allows you to create custom hooks for reusable logic.

Professional Explanation

Hooks represent a paradigm shift in React development, enabling functional components to handle complex state management and side effects. They promote:

  • Logic Reusability: Custom hooks encapsulate and share stateful logic
  • Code Organization: Related logic stays together in hooks
  • Simpler Testing: Hooks can be tested in isolation
  • Better TypeScript Support: Improved type inference with hooks
  • Reduced Boilerplate: No more classes, constructors, or bind methods

In enterprise development, hooks are the standard for writing React components. They enable cleaner code organization, better separation of concerns, and easier maintenance.

6.2 useState Hook

Simple Explanation

useState is the most basic hook. It lets you add state to functional components. You call it with an initial value, and it returns an array with two things: the current state value and a function to update it.

Think of useState like a box where you can store a value. The box has two handles: one to see what's inside (the current value) and one to put something new inside (the update function).

Technical Explanation

useState is a hook that manages local state in functional components. It returns a stateful value and a function to update it. The update function can accept either a new value or a function that receives the previous state.

Key characteristics: - Initial value: Can be any JavaScript value or a function - Lazy initialization: Use a function for expensive computations - Functional updates: Use previous state for reliable updates - Multiple states: Use multiple useState calls - State batching: Updates are batched for performance

Professional Explanation

useState is the foundation of React's state management. Understanding its behavior is crucial for building reliable components.

Important concepts: - State isolation: Each useState call is independent - Update scheduling: State updates are asynchronous - Merge behavior: useState replaces state (unlike setState in classes) - Optimization: Use multiple useState calls for unrelated state - TypeScript: Generics allow type-safe state management

6.3 useEffect Hook

Simple Explanation

useEffect lets you perform side effects in functional components. Side effects are things like fetching data, setting up subscriptions, or manually changing the DOM. You can think of useEffect as a way to tell React to do something after the component renders.

Think of useEffect as a "do this after rendering" function. It runs after the browser has painted the screen, so you can safely perform operations that affect the DOM or external systems.

Technical Explanation

useEffect is a hook that handles side effects in functional components. It runs after the component renders and can optionally clean up before the component unmounts or before the next effect runs.

Key characteristics: - Timing: Runs after the browser paints (by default) - Dependencies: Controls when the effect runs - Cleanup: Return function for cleaning up subscriptions - Multiple effects: Can use multiple useEffect calls - Scheduling: useLayoutEffect for synchronous effects

Professional Explanation

Understanding useEffect is crucial for handling side effects correctly. Common pitfalls include dependency arrays and cleanup functions.

Common use cases: - Data fetching: API calls on mount or when dependencies change - Subscriptions: Event listeners, WebSocket connections - DOM manipulation: Interacting with the DOM after render - Logging: Analytics and debugging - Timers: setTimeout, setInterval

            <ul>

            </ul>
        </div>
    );
}

6.4 useMemo Hook

Simple Explanation

useMemo is a performance optimization hook that memoizes the result of a computation. It "remembers" the value from the previous render and only recomputes it when its dependencies change.

Think of useMemo like a cache - if the inputs haven't changed, use the cached result instead of recomputing everything. This is especially useful for expensive calculations.

Technical Explanation

useMemo memoizes the result of a function and returns the cached value when dependencies haven't changed. It runs during rendering and should be used for expensive computations.

Key characteristics: - Memoization: Caches computed values - Dependencies: Controls when to recompute - Performance: Optimizes expensive calculations - Render phase: Runs during rendering - Type safety: Returns the value type

Professional Explanation

useMemo is essential for performance optimization but should be used judiciously.

When to use useMemo: - Expensive computations: Large data processing - Reference equality: Maintaining stable object references - Complex derivations: Derived state that's expensive - Preventing re-renders: Used with React.memo

When NOT to use useMemo: - Simple values: Primitive values and simple operations - Every computation: The overhead of memoization might be higher - Side effects: Use useEffect for side effects

useMemo Examples

// Basic useMemo
function ExpensiveComponent({ numbers }) {
    // Only recompute when numbers changes
    const sum = useMemo(() => {
        console.log('Calculating sum...');
        return numbers.reduce((acc, n) => acc + n, 0);
    }, [numbers]);

    return <div>Sum: {sum}</div>;
}

// With filtering and sorting
function ProductList({ products, filterCategory, sortBy }) {
    // Filter products - only recompute when dependencies change
    const filteredProducts = useMemo(() => {
        console.log('Filtering products...');
        return products.filter(p => 
            filterCategory ? p.category === filterCategory : true
        );
    }, [products, filterCategory]);

    // Sort products - only recompute when filtered products or sort changes
    const sortedProducts = useMemo(() => {
        console.log('Sorting products...');
        return [...filteredProducts].sort((a, b) => {
            if (sortBy === 'price') return a.price - b.price;
            if (sortBy === 'name') return a.name.localeCompare(b.name);
            return 0;
        });
    }, [filteredProducts, sortBy]);

    return (
        <div>
            {sortedProducts.map(product => (
                <div key={product.id}>
                    {product.name} - ${product.price}
                </div>
            ))}
        </div>
    );
}

6.5 useCallback Hook

Simple Explanation

useCallback is similar to useMemo but for functions. It memoizes a function reference, so it doesn't get recreated on every render. This is useful when passing callbacks to child components that might otherwise re-render unnecessarily.

Think of useCallback as a way to "remember" a function. If the dependencies haven't changed, use the same function instance instead of creating a new one.

Technical Explanation

useCallback returns a memoized version of the callback that only changes if one of the dependencies has changed. It prevents unnecessary function re-creation and can optimize child component rendering.

Key characteristics: - Memoization: Caches function references - Dependencies: Controls when to create new function - Performance: Prevents unnecessary re-renders - Stable references: Maintains function identity - Common with React.memo: Used together for optimization

Professional Explanation

useCallback is crucial for optimizing React applications with many components.

When to use useCallback: - Child components: When using React.memo - Event handlers: Functions passed as props - Custom hooks: Returning stable callbacks - Dependency arrays: Used in useEffect dependencies

When NOT to use useCallback: - Simple components: No child components that need optimization - Over-optimization: The overhead might not be worth it - No dependencies: Function doesn't depend on any state

useCallback Examples

// Basic useCallback
function Parent() {
    const [count, setCount] = useState(0);
    const [otherState, setOtherState] = useState(0);

    // This function will be recreated every render
    const handleIncrement = () => {
        setCount(count + 1);
    };

    // This function will be memoized
    const handleDecrement = useCallback(() => {
        setCount(count - 1);
    }, [count]); // Recreate when count changes

    return (
        <div>
            <Child onIncrement={handleIncrement} /> {/* Gets new function every time */}
            <Child onDecrement={handleDecrement} /> {/* Gets stable function */}
        </div>
    );
}

function useAsyncAction(action, dependencies = []) {

            return result;

            setError(err.message);
            throw err;
        } finally {
            setLoading(false);
        }
    }, [action]); // Recreate when action changes

    return { execute, loading, error };
}

6.6 useRef Hook

Simple Explanation

useRef creates a mutable reference that persists for the entire lifecycle of the component. It's like a "storage box" that can hold any value and doesn't cause re-renders when changed. It's commonly used to access DOM elements directly.

Think of useRef as a way to "point to" something - like a physical pointer that stays the same even as the component re-renders. You can use it to store values that shouldn't trigger re-renders or to interact with DOM elements directly.

Technical Explanation

useRef returns a mutable object with a current property. The object persists for the component's lifetime and doesn't cause re-renders when updated. It's commonly used for DOM references, timers, and storing mutable values.

Key characteristics: - Mutable: Can change current value without re-rendering - Persistent: Same reference across renders - DOM access: Access and manipulate DOM elements - Stable references: Useful for keeping values without re-renders - No dependencies: Doesn't trigger effects

Professional Explanation

useRef is versatile and has several important use cases in enterprise applications:

Common use cases: - DOM manipulation: Direct access to DOM elements - Imperative API: Integrating with non-React libraries - Value persistence: Storing values across renders - Avoiding re-renders: Storing values that don't affect UI - Previous values: Tracking previous props or state - Focus management: Controlling input focus

useRef Examples

// Storing mutable values without re-rendering
function TimerWithRef() {
    const [seconds, setSeconds] = useState(0);
    const intervalRef = useRef(null);

    const startTimer = () => {
        if (intervalRef.current) return;
        intervalRef.current = setInterval(() => {
            setSeconds(prev => prev + 1);
        }, 1000);
    };

    const stopTimer = () => {
        if (intervalRef.current) {
            clearInterval(intervalRef.current);
            intervalRef.current = null;
        }
    };

    useEffect(() => {
        // Cleanup on unmount
        return () => {
            if (intervalRef.current) {
                clearInterval(intervalRef.current);
            }
        };
    }, []);

    return (
        <div>
            <p>Seconds: {seconds}</p>
            <button onClick={startTimer}>Start</button>
            <button onClick={stopTimer}>Stop</button>
            <button onClick={() => setSeconds(0)}>Reset</button>
        </div>
    );
}

// Measuring DOM elements
function MeasureElement() {
    const [rect, setRect] = useState({ width: 0, height: 0 });
    const elementRef = useRef(null);

    const measureElement = () => {
        if (elementRef.current) {
            const { width, height } = elementRef.current.getBoundingClientRect();
            setRect({ width, height });
        }
    };

    useEffect(() => {
        // Measure initially
        measureElement();

        // Measure on resize
        const handleResize = () => measureElement();
        window.addEventListener('resize', handleResize);
        return () => window.removeEventListener('resize', handleResize);
    }, []);

    return (
        <div>
            <div ref={elementRef} className="measured-element">
                <p>Width: {rect.width}px</p>
                <p>Height: {rect.height}px</p>
            </div>
            <button onClick={measureElement}>Remeasure</button>
        </div>
    );
}

6.7 useContext Hook

Simple Explanation

useContext provides a way to share data across components without passing props down through every level of the component tree. It's like having a "global" state that any component can access directly.

Think of Context like a shared bulletin board - any component can post information there, and any component can read from it without going through intermediaries.

Technical Explanation

useContext is a hook that reads and subscribes to context changes. It accepts a context object (created with React.createContext) and returns the current context value. When the context changes, components using useContext re-render.

Key characteristics: - Global state: Share data across component tree - Avoid prop drilling: No need to pass props through intermediate components - Dynamic updates: Components re-render when context changes - Multiple contexts: Use multiple contexts for different concerns - Provider pattern: Wrap components to provide context values

Professional Explanation

Context is essential for enterprise React applications for managing:

  • Theme: Light/dark mode, branding
  • Authentication: User session, permissions
  • Internationalization: Language, locale
  • Configuration: Feature flags, settings
  • State management: Replacing or complementing libraries

However, context should be used judiciously: - Performance: Context updates cause all consumers to re-render - Overuse: Too many contexts can make code harder to follow - State management: For complex state, consider state management libraries

Simple Explanation

useReducer is like useState but more powerful. It's used for managing complex state logic where the next state depends on the previous state and an action. Think of it as a state machine - you define how state changes in response to actions.

If useState is like a simple light switch (on/off), useReducer is like a sophisticated traffic light (red, yellow, green) with clear rules for how to change states.

useReducer is a hook that manages state with a reducer function. It's similar to useState but more suitable for complex state logic with multiple sub-values or when the next state depends on the previous state.

  • Performance: Can be more performant than useState for complex state

Common patterns: - Counter: Simple increment/decrement - Form state: Managing multiple form fields - Fetch state: Loading, success, error states - Shopping cart: Adding, removing, updating items - Game state: Complex game mechanics

        loading: false,
        error: null

        dispatch({ type: 'FETCH_START' });

        try {
            const response = await fetch('/api/data');

            dispatch({ type: 'FETCH_SUCCESS', payload: data });
        } catch (error) {
            dispatch({ type: 'FETCH_ERROR', payload: error.message });
        }
    };

    useEffect(() => {
        fetchData();
    }, []);

    if (state.loading) return <div>Loading...</div>;
    if (state.error) return <div>Error: {state.error}</div>;
    return <pre>{JSON.stringify(state.data, null, 2)}</pre>;
}

6.9 useLayoutEffect Hook

Simple Explanation

useLayoutEffect is similar to useEffect, but it runs synchronously after all DOM mutations and before the browser paints. This means you can use it to measure or manipulate the DOM before the user sees any visual updates.

Think of useLayoutEffect as a "do this right before painting" function. It's useful when you need to read layout or synchronously re-render to avoid flickering.

Technical Explanation

useLayoutEffect runs synchronously after DOM mutations but before the browser paints. It's useful for DOM measurements, layout modifications, and preventing visual flickering. However, it can impact performance if used heavily.

Key characteristics: - Synchronous: Runs before the browser paints - DOM access: Can safely read and modify DOM - Visual flicker: Prevents visual flickering - Performance: Can impact performance if not used carefully - Server-side: Not available during server-side rendering

Professional Explanation

When to use useLayoutEffect: - DOM measurements: Reading element dimensions - Layout animations: Animations that depend on layout - DOM mutations: Mutations that must happen before paint - Integration: Third-party libraries that need DOM access - Preventing flicker: Updates that need to be synchronous

When to use useEffect: - Most side effects - Data fetching - Subscriptions - Timers - Analytics

Simple Explanation

useImperativeHandle allows you to customize the instance value that's exposed to parent components when using refs. It's used with forwardRef to control what methods or properties are accessible from the parent.

Technical Explanation

useImperativeHandle customizes the ref handle exposed to parent components. It's used with forwardRef to limit what parent components can do with the ref, exposing only a specific API.

Key characteristics: - Controlled access: Limit what parent components can access - ForwardRef: Used with forwardRef for ref forwarding - Clean API: Expose only necessary methods - Encapsulation: Hide internal implementation details - Testing: Easier to test specific methods

Professional Explanation

Use cases for useImperativeHandle: - Form components: Expose validation or reset methods - Animation libraries: Control animation methods - Third-party integration: Controlled access to external libraries - DOM manipulation: Controlled access to DOM elements - Imperative API: When you need imperative methods

6.11 useTransition and useDeferredValue

Simple Explanation

useTransition and useDeferredValue are hooks for improving performance by managing how updates are scheduled. They allow you to mark certain updates as non-urgent, so React can prioritize other updates that are more important for user interaction.

Think of these hooks as traffic controllers - they help decide which updates are urgent (like typing in an input) and which can wait (like rendering search results).

Technical Explanation

These hooks are part of React's Concurrent Mode features, allowing you to mark updates as "transitions" or "deferred" to improve user experience.

useTransition: - Returns a pending state and a startTransition function - Allows marking updates as non-urgent - Shows pending state during transitions - Keeps UI responsive during heavy updates

useDeferredValue: - Returns a deferred version of a value - Updates the deferred value later if more urgent updates occur - Useful for showing stale data during updates - Similar to debouncing but integrated with React's scheduling

Professional Explanation

When to use useTransition: - Search/Filter: Heavy filtering while typing - Large lists: Rendering large data sets - Complex transitions: Navigation between pages - Data fetching: Loading data without blocking UI

When to use useDeferredValue: - Real-time updates: Data updates that can be delayed - Search results: Showing results while typing - Large computations: Expensive calculations that can be delayed - Smooth UI: Maintaining smooth user experience

6.13 Custom Hooks

Simple Explanation

Custom Hooks let you extract reusable logic from components into reusable functions. They allow you to share stateful logic across multiple components without duplicating code.

Think of custom hooks like recipe templates - instead of writing the same code over and over, you create a reusable "recipe" that you can use in different components.

Technical Explanation

Custom hooks are JavaScript functions that use React hooks. They allow you to extract component logic into reusable functions. Custom hooks follow the same rules as built-in hooks and can use other hooks.

Key characteristics: - Reusable: Share logic across components - Composable: Can use other hooks - Encapsulated: Hide implementation details - Testable: Can be tested independently - Naming: Must start with "use"

Professional Explanation

Best practices for custom hooks: - Single responsibility: Do one thing well - Composable: Build complex hooks from simple ones - Documented: Clear purpose and API - Tested: Unit tests for hook logic - Type-safe: Use TypeScript for type safety

Common custom hook examples: - useLocalStorage: Sync with localStorage - useFetch: Data fetching with loading/error states - useDebounce: Debounce values - useToggle: Boolean state management - useMediaQuery: Responsive design helpers

Custom Hooks Examples

// useLocalStorage - Persist state in localStorage
function useLocalStorage(key, initialValue) {
    const [storedValue, setStoredValue] = useState(() => {
        try {
            const item = localStorage.getItem(key);
            return item ? JSON.parse(item) : initialValue;
        } catch (error) {
            console.error(error);
            return initialValue;
        }
    });

    const setValue = (value) => {
        try {
            const valueToStore = value instanceof Function ? value(storedValue) : value;
            setStoredValue(valueToStore);
            localStorage.setItem(key, JSON.stringify(valueToStore));
        } catch (error) {
            console.error(error);
        }
    };

    return [storedValue, setValue];
}

// Using useLocalStorage
function ThemePreference() {
    const [theme, setTheme] = useLocalStorage('theme', 'light');

    return (
        <div>
            <p>Current theme: {theme}</p>
            <button onClick={() => setTheme('light')}>Light</button>
            <button onClick={() => setTheme('dark')}>Dark</button>
        </div>
    );
}

// useFetch - Data fetching hook
function useFetch(url, options = {}) {
    const [data, setData] = useState(null);
    const [loading, setLoading] = useState(true);
    const [error, setError] = useState(null);

    useEffect(() => {
        const abortController = new AbortController();

        const fetchData = async () => {
            try {
                setLoading(true);
                setError(null);

                const response = await fetch(url, {
                    ...options,
                    signal: abortController.signal
                });

                if (!response.ok) {
                    throw new Error(`HTTP error! status: ${response.status}`);
                }

                const json = await response.json();
                setData(json);
            } catch (error) {
                if (error.name !== 'AbortError') {
                    setError(error.message);
                }
            } finally {
                setLoading(false);
            }
        };

        fetchData();

        return () => {
            abortController.abort();
        };
    }, [url, JSON.stringify(options)]);

    return { data, loading, error };
}

// Using useFetch
function UserList() {
    const { data: users, loading, error } = useFetch('/api/users');

    if (loading) return <div>Loading...</div>;
    if (error) return <div>Error: {error}</div>;

    return (
        <ul>
            {users?.map(user => (
                <li key={user.id}>{user.name}</li>
            ))}
        </ul>
    );
}

// useDebounce - Debounce values
function useDebounce(value, delay = 500) {
    const [debouncedValue, setDebouncedValue] = useState(value);

    useEffect(() => {
        const timer = setTimeout(() => {
            setDebouncedValue(value);
        }, delay);

        return () => {
            clearTimeout(timer);
        };
    }, [value, delay]);

    return debouncedValue;
}

// Using useDebounce
function SearchWithDebounce() {
    const [searchTerm, setSearchTerm] = useState('');
    const debouncedSearchTerm = useDebounce(searchTerm, 300);
    const [results, setResults] = useState([]);

    useEffect(() => {
        if (debouncedSearchTerm) {
            // Search API call with debounced value
            searchItems(debouncedSearchTerm).then(setResults);
        }
    }, [debouncedSearchTerm]);

    return (
        <div>
            <input
                value={searchTerm}
                onChange={(e) => setSearchTerm(e.target.value)}
                placeholder="Search..."
            />
            <div>
                {results.map(item => (
                    <div key={item.id}>{item.name}</div>
                ))}
            </div>
        </div>
    );
}

// useMediaQuery - Responsive design
function useMediaQuery(query) {
    const [matches, setMatches] = useState(() => {
        if (typeof window !== 'undefined') {
            return window.matchMedia(query).matches;
        }
        return false;
    });

    useEffect(() => {
        const mediaQuery = window.matchMedia(query);
        const handler = (event) => setMatches(event.matches);

        mediaQuery.addEventListener('change', handler);
        return () => mediaQuery.removeEventListener('change', handler);
    }, [query]);

    return matches;
}

// Using useMediaQuery
function ResponsiveComponent() {
    const isMobile = useMediaQuery('(max-width: 640px)');
    const isTablet = useMediaQuery('(min-width: 641px) and (max-width: 1024px)');
    const isDesktop = useMediaQuery('(min-width: 1025px)');

    return (
        <div>
            {isMobile && <MobileLayout />}
            {isTablet && <TabletLayout />}
            {isDesktop && <DesktopLayout />}
        </div>
    );
}

// useToggle - Toggle state
function useToggle(initialValue = false) {
    const [state, setState] = useState(initialValue);

    const toggle = useCallback(() => {
        setState(prev => !prev);
    }, []);

    const setTrue = useCallback(() => {
        setState(true);
    }, []);

    const setFalse = useCallback(() => {
        setState(false);
    }, []);

    return { state, toggle, setTrue, setFalse };
}

// Using useToggle
function ModalControl() {
    const { state: isOpen, toggle, setTrue, setFalse } = useToggle(false);

    return (
        <div>
            <button onClick={setTrue}>Open Modal</button>
            {isOpen && (
                <div className="modal">
                    <div className="modal-content">
                        <h2>Modal</h2>
                        <p>Modal content here</p>
                        <button onClick={setFalse}>Close</button>
                    </div>
                </div>
            )}
        </div>
    );
}

6.14 Common Mistakes and Best Practices

6.14.1 Common Mistakes

// ❌ Calling hooks conditionally
function BadComponent({ condition }) {
    const [count, setCount] = useState(0); // ✅ Always runs

    if (condition) {
        const [data, setData] = useState(null); // ❌ Conditional hook
    }
}

// ✅ Calling hooks at top level
function GoodComponent({ condition }) {
    const [count, setCount] = useState(0);
    const [data, setData] = useState(null);

    // Use condition inside the hook
    useEffect(() => {
        if (condition) {
            // Do something
        }
    }, [condition]);
}

// ❌ Missing dependencies in useEffect
function BadEffect({ userId }) {
    const [user, setUser] = useState(null);

    useEffect(() => {
        fetchUser(userId).then(setUser);
    }, []); // ❌ Missing userId dependency
}

// ✅ Including all dependencies
function GoodEffect({ userId }) {
    const [user, setUser] = useState(null);

    useEffect(() => {
        fetchUser(userId).then(setUser);
    }, [userId]); // ✅ userId included
}

// ❌ Stale closure in useEffect
function StaleClosure() {
    const [count, setCount] = useState(0);

    useEffect(() => {
        const interval = setInterval(() => {
            console.log(count); // ❌ Always logs initial count
        }, 1000);

        return () => clearInterval(interval);
    }, []); // Empty dependency array
}

// ✅ Fixing stale closure
function FixedClosure() {
    const [count, setCount] = useState(0);

    useEffect(() => {
        const interval = setInterval(() => {
            setCount(prev => {
                console.log(prev);
                return prev;
            });
        }, 1000);

        return () => clearInterval(interval);
    }, []);
}

// ❌ Mutating refs during render
function BadRef() {
    const ref = useRef(0);
    ref.current = 5; // ❌ Mutation during render

    return <div>{ref.current}</div>;
}

// ✅ Mutating refs in effects
function GoodRef() {
    const ref = useRef(0);

    useEffect(() => {
        ref.current = 5; // ✅ Mutation in effect
    }, []);

    return <div>{ref.current}</div>;
}

6.15 Interview Questions

Junior Level Questions

Q: What are React Hooks and why were they introduced?

Answer: Hooks are functions that let you use React features from functional components. They were introduced to: 1. Use state and lifecycle in functional components 2. Share logic between components 3. Reduce complexity compared to classes 4. Better performance and readability

// Before: Class component
class Counter extends React.Component {
    state = { count: 0 };
    render() {
        return <button onClick={() => this.setState({ count: this.state.count + 1 })}>
            {this.state.count}
        </button>;
    }
}

// After: Functional component with hooks
function Counter() {
    const [count, setCount] = useState(0);
    return <button onClick={() => setCount(count + 1)}>{count}</button>;
}

Q: What are the rules of Hooks?

Answer: 1. Only call hooks at the top level - Not inside loops, conditions, or nested functions 2. Only call hooks from React functions - Functional components or custom hooks

Mid Level Questions

Q: Explain the difference between useState and useReducer.

Answer: - useState: For simple state, single value, or object - useReducer: For complex state logic, multiple sub-values, or when next state depends on previous

// useState
const [count, setCount] = useState(0);

// useReducer
const [state, dispatch] = useReducer(reducer, { count: 0 });

Q: When should you use useMemo vs useCallback?

Answer: - useMemo: Memoizes values/computations - useCallback: Memoizes functions

// useMemo for values
const processedData = useMemo(() => {
    return heavyComputation(data);
}, [data]);

// useCallback for functions
const handleClick = useCallback(() => {
    console.log('Clicked');
}, []);

Senior Level Questions

Q: Explain the dependency array in useEffect and common pitfalls.

Answer: The dependency array controls when the effect runs. Common pitfalls include: 1. Missing dependencies: Leading to stale closures 2. Including unnecessary dependencies: Causing unnecessary re-runs 3. Using objects/arrays: Causing infinite loops 4. Using functions: Need to use useCallback 

// ✅ Correct dependencies
useEffect(() => {
    fetchUser(userId);
}, [userId]);

// ❌ Infinite loop with object
useEffect(() => {
    fetchUser(user);
}, [user]); // user object changes every render

// ✅ Fix with useMemo
const memoizedUser = useMemo(() => user, [user.id]);
useEffect(() => {
    fetchUser(memoizedUser);
}, [memoizedUser]);

Q: How do you optimize performance with hooks?

Answer: 1. useMemo: Cache expensive computations 2. useCallback: Memoize callbacks 3. React.memo: Prevent re-renders 4. useTransition: Mark non-urgent updates 5. useDeferredValue: Defer heavy updates 6. useId: Stable IDs for accessibility

const MemoizedComponent = React.memo(({ data }) => {
    const processed = useMemo(() => processData(data), [data]);
    const handleClick = useCallback(() => handleItem(data.id), [data.id]);

    return <div onClick={handleClick}>{processed}</div>;
});
