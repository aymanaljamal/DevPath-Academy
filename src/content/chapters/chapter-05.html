React Fundamentals

5.1 Introduction to React Fundamentals

Simple Explanation

React Fundamentals are the building blocks of every React application. Think of them as the ABCs of React - once you master these concepts, you can build anything from a simple button to a complex enterprise application. These fundamentals include JSX (the HTML-like syntax), Components (the building blocks), Props (data passing), State (component memory), and the Component Lifecycle (birth, life, and death of components).

Imagine building with LEGO blocks: - JSX is how you describe what each block looks like - Components are the individual LEGO blocks - Props are like the instructions for how blocks connect - State is like the memory of what's been built - Lifecycle is the process of building, changing, and dismantling

Technical Explanation

React Fundamentals form the core API and patterns of React. These include:

  1. JSX: A syntax extension that allows writing HTML-like code in JavaScript
  2. Components: Functions or classes that return UI elements
  3. Props: Read-only data passed from parent to child
  4. State: Mutable data that triggers re-renders when changed
  5. Lifecycle: The sequence of events from component creation to destruction
  6. Rendering: The process of converting components to DOM elements
  7. Conditional Rendering: Showing different UI based on conditions
  8. Lists and Keys: Rendering collections of elements with unique identifiers

Professional Explanation

In enterprise React development, mastering fundamentals is crucial for:

  • Performance Optimization: Understanding rendering cycles and memoization
  • Architecture Decisions: Choosing between patterns and approaches
  • Code Quality: Writing maintainable and testable components
  • Team Collaboration: Following consistent patterns and best practices
  • Debugging: Understanding the component tree and data flow
  • Scalability: Building components that grow with the application

5.2 JSX (JavaScript XML)

Simple Explanation

JSX allows you to write HTML-like code inside your JavaScript files. It's a syntax extension that makes React code look like HTML, making it easier to understand and write. Under the hood, JSX gets transformed into regular JavaScript function calls.

Think of JSX as a bridge between HTML and JavaScript - it lets you write what looks like HTML but with the full power of JavaScript embedded within.

Technical Explanation

JSX is a syntax extension for JavaScript that resembles HTML. It allows you to write markup and logic together in a single file. JSX is transformed by tools like Babel into React.createElement() calls.

Key characteristics: - HTML-like syntax: Closer to what you see in the browser - JavaScript expressions: Embed JavaScript inside {} - Self-closing tags: Tags can be self-closed like <img /> - Fragments: Empty tags <> for grouping without extra DOM nodes - Attributes: camelCase for properties (e.g., className instead of class)

Professional Explanation

JSX is a compile-time syntactic sugar that follows the XML/HTML syntax. It provides type safety and linting capabilities when used with TypeScript and ESLint plugins. The JSX transform converts JSX to React.createElement calls, enabling React's virtual DOM reconciliation.

JSX features for enterprise: - TypeScript integration: Type checking for props and attributes - Custom components: Capitalized names distinguish from HTML elements - Expression interpolation: Full JavaScript expressions in {} - Spread attributes: {...props} for passing multiple props - Conditional rendering: Using JavaScript expressions

JSX Rules and Best Practices

// ✅ DO: Use camelCase for attributes
<input type="text" className="input" htmlFor="name" />

// ❌ DON'T: Use HTML attribute names
<input type="text" class="input" for="name" />

// ✅ DO: Use expressions for dynamic content
const message = <h1>{dynamicContent}</h1>;

// ❌ DON'T: Use plain JavaScript in JSX
// This is incorrect:
// const message = <h1>if (condition) { 'Hello' }</h1>;

// ✅ DO: Use conditional operators
const result = <div>{condition ? 'Yes' : 'No'}</div>;

// ✅ DO: Use fragment for multiple elements

    <>
        <Header />
        <Content />
        <Footer />
    </>
);

// ❌ DON'T: Use non-self-closing for empty elements
// <Image src="photo.jpg" alt="Photo"></Image>

// ✅ DO: Use {props.children} for child content
function Card({ children }) {
    return <div className="card">{children}</div>;

5.3 Components

Simple Explanation

Components are the heart of React. They are reusable pieces of UI that can be combined to build complex interfaces. Think of them as custom HTML elements that you create - each component has its own structure, style, and behavior.

A React application is a tree of components, starting from a root component and branching out into smaller, more specialized components.

Technical Explanation

Components are JavaScript functions or classes that accept inputs (props) and return React elements (JSX). They follow the principle of composition - building complex UIs from smaller, focused pieces.

Component types: 1. Functional Components: Simple functions that return JSX 2. Class Components: ES6 classes with lifecycle methods (legacy) 3. Pure Components: Components that implement shallow comparison 4. Higher-Order Components (HOCs): Functions that wrap components 5. Render Props: Components that accept a function as a prop

Professional Explanation

In enterprise React, components are the primary unit of code organization. They follow the Single Responsibility Principle, each handling a specific piece of UI and logic.

Component architecture considerations: - Component Categories: Presentational vs Container components - Component Hierarchy: Smart vs Dumb components - Component Reusability: Designing for reuse across the application - Component Composition: Building complex components from simpler ones - Component Testing: Unit testing components in isolation - Component Documentation: Documenting props and usage

// Class component with lifecycle methods
class DataFetcher extends React.Component {
    constructor(props) {
        super(props);
        this.state = {
            data: null,
            loading: true,
            error: null
        };
    }

    componentDidMount() {
        this.fetchData();
    }

    componentDidUpdate(prevProps) {
        if (prevProps.url !== this.props.url) {
            this.fetchData();
        }
    }

    componentWillUnmount() {
        // Cleanup subscriptions
        if (this.abortController) {
            this.abortController.abort();
        }
    }

    async fetchData() {
        try {
            this.setState({ loading: true, error: null });
            const response = await fetch(this.props.url);
            const data = await response.json();
            this.setState({ data, loading: false });
        } catch (error) {
            this.setState({ error: error.message, loading: false });
        }
    }

    render() {
        const { data, loading, error } = this.state;

        if (loading) return <div>Loading...</div>;
        if (error) return <div>Error: {error}</div>;
        return <div>{JSON.stringify(data)}</div>;
    }
}

5.4 Props

Simple Explanation

Props (short for properties) are how components communicate with each other. They are like arguments you pass to a function - you send data from a parent component to a child component, and the child component uses that data to render itself.

Think of props as the ingredients you give to a recipe. The recipe (component) uses these ingredients (props) to create the final dish (UI).

Technical Explanation

Props are read-only inputs to React components. They flow from parent to child (unidirectional data flow). Props can be any JavaScript value: strings, numbers, booleans, arrays, objects, functions, or even React components.

Key characteristics: - Read-only: Components cannot modify their own props - Immutability: Props should never be mutated - Type checking: PropTypes or TypeScript for validation - Default values: Can be defined for optional props - Children: Special prop for nested content

Professional Explanation

Props are the primary mechanism for data flow in React applications. They implement a unidirectional data flow pattern, making the application predictable and easier to debug.

Prop management strategies: - Prop Types: Runtime type checking with PropTypes - TypeScript: Compile-time type checking - Default Props: Default values for optional props - Prop Drilling: Passing props through multiple levels - Context API: For props needed in many components - Composition: Using children instead of passing many props

Props Patterns

// Render props pattern
function DataFetcher({ url, render }) {
    const [data, setData] = useState(null);
    const [loading, setLoading] = useState(true);
    const [error, setError] = useState(null);

    useEffect(() => {
        fetchData();
    }, [url]);

    async function fetchData() {
        try {
            setLoading(true);
            const response = await fetch(url);
            const json = await response.json();
            setData(json);
        } catch (err) {
            setError(err.message);
        } finally {
            setLoading(false);
        }
    }

    return render({ data, loading, error });
}

// Using render props
function UserList() {
    return (
        <DataFetcher
            url="/api/users"
            render={({ data, loading, error }) => {
                if (loading) return <div>Loading...</div>;
                if (error) return <div>Error: {error}</div>;

                return (
                    <ul>
                        {data.map(user => (
                            <li key={user.id}>{user.name}</li>
                        ))}
                    </ul>
                );
            }}
        />
    );
}

// Higher-Order Component (HOC) pattern
function withLoading(WrappedComponent) {
    return function WithLoadingComponent({ isLoading, ...props }) {
        if (isLoading) {
            return <div>Loading...</div>;
        }
        return <WrappedComponent {...props} />;
    };
}

// Using HOC
const UserListWithLoading = withLoading(UserList);

function Users() {
    const [users, setUsers] = useState([]);
    const [loading, setLoading] = useState(true);

    useEffect(() => {
        fetchUsers();
    }, []);

    async function fetchUsers() {

        const data = await response.json();
        setUsers(data);
        setLoading(false);
    }

    return <UserListWithLoading isLoading={loading} users={users} />;
}

5.5 State

Simple Explanation

State is the memory of a component. It's data that can change over time and when it changes, React automatically re-renders the component to show the updated information. Unlike props (which come from a parent), state is internal to the component and can be changed by the component itself.

Think of state as the current state of a toggled light switch - it can be on or off, and the component responds to changes by displaying the appropriate UI.

Technical Explanation

State is mutable data that a component maintains over its lifetime. When state changes, React schedules a re-render to update the UI. State is local and private to the component that creates it.

Key characteristics: - Mutable: Can be changed using setState or useState - Local: Belongs to the component that defines it - Asynchronous: State updates are batched and asynchronous - Triggers re-render: State changes cause component to re-render - Hook-based: Managed with useState or useReducer hooks

Professional Explanation

State management is central to React applications. Understanding state helps create predictable, performant applications.

State management strategies: - Local State: useState for component-specific data - Reducer State: useReducer for complex state logic - Global State: Context API or state management libraries - Server State: React Query for server data synchronization - URL State: Routing parameters and query strings

function UserForm() {

    const [email, setEmail] = useState('');
    const [age, setAge] = useState('');

        if (!name) validationErrors.name = 'Name is required';
        if (!email) validationErrors.email = 'Email is required';
        if (!email.includes('@')) validationErrors.email = 'Invalid email';

        if (Object.keys(validationErrors).length > 0) {
            setErrors(validationErrors);
            setIsSubmitting(false);
            return;
        }

        try {
            // Submit form
            await submitUser({ name, email, age });
            // Success logic
        } catch (error) {
            setErrors({ submit: error.message });
        } finally {
            setIsSubmitting(false);
        }
    };

    return (
        <form onSubmit={handleSubmit}>
            <div>
                <label>Name:</label>
                <input
                    value={name}
                    onChange={e => setName(e.target.value)}
                    className={errors.name ? 'error' : ''}
                />
                {errors.name && <span>{errors.name}</span>}
            </div>
            <div>
                <label>Email:</label>

                    value={email}

            </div>
            <div>
                <label>Age:</label>
                <input
                    type="number"
                    value={age}
                    onChange={e => setAge(e.target.value)}
                />
            </div>
            {errors.submit && <div>{errors.submit}</div>}
            <button type="submit" disabled={isSubmitting}>
                {isSubmitting ? 'Submitting...' : 'Submit'}
            </button>
        </form>
    );
}

// Object state with useState
function SettingsPanel() {
    const [settings, setSettings] = useState({
        theme: 'light',
        notifications: true,
        language: 'en',
        privacy: {
            profileVisibility: 'public',
            emailVisibility: 'private'
        }
    });

    const updateSetting = (key, value) => {
        setSettings(prev => ({
            ...prev,
            [key]: value
        }));
    };

    const updateNestedSetting = (key1, key2, value) => {
        setSettings(prev => ({
            ...prev,
            [key1]: {
                ...prev[key1],
                [key2]: value
            }
        }));
    };

    return (
        <div>
            <label>
                <input
                    type="checkbox"
                    checked={settings.notifications}
                    onChange={e => updateSetting('notifications', e.target.checked)}
                />
                Enable notifications
            </label>

            <select
                value={settings.theme}
                onChange={e => updateSetting('theme', e.target.value)}
            >

// useReducer for complex state logic
const initialState = {
    count: 0,
    history: [],
    isLoading: false,
    error: null
};

const reducer = (state, action) => {
    switch (action.type) {
        case 'INCREMENT':
            return {
                ...state,
                count: state.count + 1,
                history: [...state.history, { type: 'INCREMENT', value: state.count + 1 }]
            };

        case 'DECREMENT':
            return {
                ...state,
                count: state.count - 1,
                history: [...state.history, { type: 'DECREMENT', value: state.count - 1 }]
            };

        case 'RESET':
            return {
                ...state,
                count: 0,
                history: []
            };

        case 'SET_LOADING':
            return {
                ...state,
                isLoading: action.payload
            };

        case 'SET_ERROR':
            return {
                ...state,
                error: action.payload
            };

        default:
            return state;
    }
};

function CounterWithReducer() {
    const [state, dispatch] = useReducer(reducer, initialState);

    const incrementAsync = async () => {
        dispatch({ type: 'SET_LOADING', payload: true });
        dispatch({ type: 'SET_ERROR', payload: null });

        try {
            await new Promise(resolve => setTimeout(resolve, 1000));
            dispatch({ type: 'INCREMENT' });
        } catch (error) {
            dispatch({ type: 'SET_ERROR', payload: error.message });
        } finally {
            dispatch({ type: 'SET_LOADING', payload: false });
        }
    };

    return (
        <div>
            <h2>Count: {state.count}</h2>
            <button onClick={() => dispatch({ type: 'INCREMENT' })}>+</button>
            <button onClick={() => dispatch({ type: 'DECREMENT' })}>-</button>
            <button onClick={() => dispatch({ type: 'RESET' })}>Reset</button>
            <button onClick={incrementAsync} disabled={state.isLoading}>
                {state.isLoading ? 'Loading...' : 'Async +1'}
            </button>

            {state.error && <div className="error">{state.error}</div>}

            <h3>History</h3>
            <ul>
                {state.history.map((item, index) => (
                    <li key={index}>
                        {item.type}: {item.value}
                    </li>
                ))}
            </ul>
        </div>
    );
}

5.6 Component Lifecycle

Simple Explanation

The component lifecycle is the journey a component goes through from being created to being destroyed. React provides hooks (for functional components) and methods (for class components) that let you run code at specific points in this journey.

Think of it like the life of a person: - Birth: The component is created (mounted) - Growth: The component changes (updates) - Death: The component is removed (unmounted)

Technical Explanation

The lifecycle consists of three main phases: 1. Mounting: Component is created and inserted into the DOM 2. Updating: Component re-renders due to state or prop changes 3. Unmounting: Component is removed from the DOM

For functional components, these are managed with useEffect and other hooks. For class components, these are managed with lifecycle methods.

Professional Explanation

Understanding the lifecycle is crucial for: - Data Fetching: When to fetch data (mounting) - DOM Manipulation: When to interact with the DOM - Resource Management: When to set up and clean up resources - Performance: When to optimize rendering - Debugging: Understanding component execution order

Functional Component Lifecycle with Hooks

// useEffect for lifecycle management
function LifecycleExample() {
    const [count, setCount] = useState(0);
    const [data, setData] = useState(null);
    const [isVisible, setIsVisible] = useState(true);

    // 1. ComponentDidMount - runs once when component mounts
    useEffect(() => {
        console.log('Component mounted');

        // Set up subscriptions
        const subscription = subscribeToData();

        // Cleanup on unmount (ComponentWillUnmount)
        return () => {
            console.log('Component unmounting');
            subscription.unsubscribe();
        };
    }, []); // Empty dependency array

    // 2. ComponentDidUpdate - runs when dependencies change
    useEffect(() => {
        console.log('Count changed to:', count);
    }, [count]); // Runs when count changes

    // 3. ComponentDidUpdate with multiple dependencies
    useEffect(() => {
        console.log('Count or data changed');
        // Both count and data cause this effect
    }, [count, data]);

    // 4. ComponentDidUpdate without dependencies - runs on every render
    useEffect(() => {
        console.log('Component rendered');
        // This runs on every render
    });

    // 5. ComponentDidMount - data fetching
    useEffect(() => {
        const fetchData = async () => {
            try {
                const response = await fetch('/api/data');
                const json = await response.json();
                setData(json);
            } catch (error) {
                console.error('Error fetching data:', error);
            }
        };

        fetchData();
    }, []); // Empty array for once

    // 6. Layout effect - runs before paint (synchronous)
    useLayoutEffect(() => {
        console.log('Layout effect - runs before paint');
        // For DOM measurements
        const element = document.getElementById('element');
        if (element) {
            const rect = element.getBoundingClientRect();
            console.log('Element position:', rect);
        }
    }, []);

    return (
        <div>
            {isVisible && (
                <div id="element">
                    <h2>Count: {count}</h2>
                    <button onClick={() => setCount(count + 1)}>Increment</button>
                    <button onClick={() => setIsVisible(false)}>Unmount</button>
                    {data && <pre>{JSON.stringify(data, null, 2)}</pre>}
                </div>
            )}
        </div>
    );
}

class LifecycleClass extends React.Component {

            return { count: 0 };
        }
        return null;
    }

    componentDidMount() {
        console.log('4. componentDidMount');
        this.fetchData();
        this.subscription = subscribeToData();
    }

    // Updating phase - before DOM
    shouldComponentUpdate(nextProps, nextState) {
        console.log('5. shouldComponentUpdate');
        // Return false to prevent re-render
        return true;
    }

    // Updating phase - before DOM
    getSnapshotBeforeUpdate(prevProps, prevState) {
        console.log('6. getSnapshotBeforeUpdate');
        // Capture DOM state before update
        return { scrollHeight: document.body.scrollHeight };
    }

    // Updating phase - after DOM
    componentDidUpdate(prevProps, prevState, snapshot) {
        console.log('7. componentDidUpdate');
        console.log('Snapshot:', snapshot);

        if (prevState.count !== this.state.count) {
            console.log('Count changed');
        }
    }

    // Unmounting phase
    componentWillUnmount() {
        console.log('8. componentWillUnmount');
        this.subscription.unsubscribe();
    }

    // Error handling
    componentDidCatch(error, errorInfo) {
        console.log('Error caught:', error, errorInfo);
        this.setState({ error: error.message });
    }

    async fetchData() {
        try {
            const response = await fetch('/api/data');
            const json = await response.json();
            this.setState({ data: json, loading: false });
        } catch (error) {
            this.setState({ error: error.message });
        }
    }

    render() {
        console.log('3. render');

        if (this.state.error) {
            return <div>Error: {this.state.error}</div>;

5.7 Rendering

Simple Explanation

Rendering is the process of converting React components into actual HTML that appears on the screen. When a component's state or props change, React "re-renders" the component to reflect the new data.

Think of rendering like a magic whiteboard - you write something, and React makes it appear on the actual page. When you change what's written, React updates only the changed parts.

Technical Explanation

Rendering in React involves: 1. Initial Render: The first time a component is rendered 2. Re-renders: When state or props change 3. Reconciliation: Comparing new and old virtual DOM 4. Commit Phase: Applying changes to the real DOM 5. Batching: Grouping multiple updates

Professional Explanation

Rendering performance is crucial for user experience. React's rendering system is designed for efficiency but requires understanding for optimization.

Rendering concepts: - Rendering Phases: Render and Commit phases - Reconciliation: Virtual DOM diffing algorithm - Batching: Automatic batching of state updates - Scheduling: Prioritizing different render tasks - Concurrent Mode: Interruptible rendering

5.9 Lists and Keys

Simple Explanation

    const [isOn, setIsOn] = useState(false);

    return children({
        isOn,
        toggle: () => setIsOn(!isOn),
        turnOn: () => setIsOn(true),
        turnOff: () => setIsOn(false)
    });
}

// Using function as child
function ToggleExample() {
    return (
        <Toggle>
            {({ isOn, toggle }) => (
                <div>
                    <button onClick={toggle}>
                        {isOn ? 'ON' : 'OFF'}
                    </button>
                    {isOn && <div>The toggle is on!</div>}
                </div>
            )}
        </Toggle>
    );
}

// Multiple children with props
function Modal({
    isOpen,
    onClose,
    title,
    children,
    footer
}) {
    if (!isOpen) return null;

    return (
        <div className="modal-overlay" onClick={onClose}>
            <div className="modal" onClick={e => e.stopPropagation()}>
                {title && (
                    <div className="modal-header">
                        <h2>{title}</h2>
                        <button className="close-btn" onClick={onClose}>×</button>
                    </div>
                )}
                <div className="modal-body">{children}</div>
                {footer && (
                    <div className="modal-footer">{footer}</div>
                )}
            </div>
        </div>
    );
}

// Using Modal with children and footer
function ConfirmDialog({ isOpen, onConfirm, onCancel, message }) {
    return (
        <Modal
            isOpen={isOpen}
            onClose={onCancel}
            title="Confirm Action"
            footer={
                <>
                    <button onClick={onConfirm} className="primary">Confirm</button>
                    <button onClick={onCancel} className="secondary">Cancel</button>
                </>
            }
        >
            <p>{message}</p>
            <div className="warning-icon">⚠️</div>
        </Modal>
    );
}

5.11 Common Mistakes and Best Practices

5.11.1 Common Mistakes

// ❌ Mutating state directly
function BadState() {
    const [items, setItems] = useState([]);

    const addItem = (item) => {
        items.push(item); // Direct mutation
        setItems(items); // No re-render
    };
}

// ✅ Using immutability
function GoodState() {
    const [items, setItems] = useState([]);

    const addItem = (item) => {
        setItems([...items, item]); // New array
    };
}

// ❌ Missing key in list
function BadList({ items }) {
    return (
        <ul>
            {items.map(item => (
                <li>{item}</li> // No key
            ))}
        </ul>
    );
}

// ✅ Using key
function GoodList({ items }) {
    return (
        <ul>
            {items.map(item => (
                <li key={item.id}>{item}</li>
            ))}
        </ul>
    );
}

// ❌ Using index as key with dynamic lists
function BadKey({ items }) {
    return (
        <ul>
            {items.map((item, index) => (
                <li key={index}>{item}</li> // Index as key
            ))}
        </ul>
    );
}

// ✅ Using unique ID
function GoodKey({ items }) {
    return (
        <ul>
            {items.map(item => (
                <li key={item.id}>{item}</li>
            ))}
        </ul>
    );
}

// ❌ Calling hooks conditionally
function BadHooks({ condition }) {
    const [count, setCount] = useState(0); // ✅

    if (condition) {
        const [data, setData] = useState(null); // ❌ Conditional hook
    }
}

// ✅ Calling hooks at top level
function GoodHooks({ condition }) {
    const [count, setCount] = useState(0);
    const [data, setData] = useState(null);

    useEffect(() => {
        if (condition) {
            // Use condition inside effect
        }
    }, [condition]);
}

5.11.2 Best Practices

// ✅ Component organization
function Component({ prop1, prop2 }) {
    // 1. Hooks
    const [state, setState] = useState();
    const dispatch = useDispatch();

    // 2. Memoized values
    const computedValue = useMemo(() => {
        return expensiveCalculation(prop1);
    }, [prop1]);

    // 3. Callbacks
    const handleClick = useCallback(() => {
        // Handle click
    }, []);

    // 4. Effects
    useEffect(() => {
        // Side effects
    }, []);

    // 5. Early returns
    if (!prop1) return <EmptyState />;

    // 6. Render
    return (
        <div>
            {/* JSX */}
        </div>
    );
}

// ✅ Destructuring props
function GoodProps({ user, onUpdate, onDelete }) {
    // Use destructured props
    return <div>{user.name}</div>;
}

// ❌ Anti-pattern
function BadProps(props) {
    // Accessing props with dot notation
    return <div>{props.user.name}</div>;
}

// ✅ Proper event handlers
function GoodHandlers() {
    const [input, setInput] = useState('');

    const handleChange = (e) => {
        setInput(e.target.value);
    };

    return <input value={input} onChange={handleChange} />;
}

5.12 Interview Questions

Junior Level Questions

Q: What is JSX and why use it?

Answer: JSX is a syntax extension for JavaScript that allows writing HTML-like code in React. Benefits include: - Visual representation of UI - Error handling and debugging - Performance optimization - Type checking support

// JSX
const element = <h1 className="title">Hello</h1>;

// Transpiled to
const element = React.createElement('h1', { className: 'title' }, 'Hello');

Q: What's the difference between props and state?

Answer: - Props: Read-only, passed from parent, immutable - State: Read/write, internal to component, mutable

function Component({ prop }) {
    const [state, setState] = useState(0);
    // Props come from parent
    // State is managed internally
}

Mid Level Questions

Q: Explain the component lifecycle and how it's handled in functional components.

Answer: The lifecycle consists of: 1. Mounting: Component creation with useEffect([]) 2. Updating: Component updates with useEffect([dependencies]) 3. Unmounting: Cleanup with useEffect return function

function Component() {
    // Mounting and unmounting
    useEffect(() => {
        console.log('Mounted');
        return () => console.log('Unmounted');
    }, []);

    // Updating
    useEffect(() => {
        console.log('Count changed');
    }, [count]);
}

Q: When should you use useMemo vs useCallback?

Answer: - useMemo: Memoizes values/computations - useCallback: Memoizes functions

function Component({ data }) {
    // Memoize computed value
    const processed = useMemo(() => {
        return heavyComputation(data);
    }, [data]);

    // Memoize callback function
    const handleClick = useCallback(() => {
        console.log('Clicked');
    }, []);

    return <div>{processed}</div>;
}

Senior Level Questions

Q: Explain the reconciliation process and how keys affect it.

Answer: Reconciliation is React's algorithm for updating the DOM efficiently. It compares the new virtual DOM with the previous one and determines what changes to make.

Keys help React identify which items have changed: 1. Unique keys: Help React track items across re-renders 2. Stable keys: Same item always has same key 3. Avoid index keys: Can cause issues with reordering

// Good - unique ID
<li key={user.id}>{user.name}</li>

// Bad - index (causes issues with reordering)
<li key={index}>{user.name}</li>

Q: How do you optimize React component performance?

Answer: 1. React.memo: Prevent unnecessary re-renders 2. useMemo: Cache expensive computations 3. useCallback: Memoize callback functions 4. Code splitting: Lazy loading with React.lazy 5. Virtualization: For large lists 6. Debouncing: For frequent updates

const MemoizedComponent = React.memo(({ data }) => {
    const processed = useMemo(() => {
        return processData(data);
    }, [data]);

    const handleClick = useCallback(() => {
        // Handle click
    }, []);

    return <div onClick={handleClick}>{processed}</div>;
});
