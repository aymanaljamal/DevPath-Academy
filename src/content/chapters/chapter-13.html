Introduction

  • React fundamentals
  • Enterprise folder structure
  • Data flow
  • Services
  • APIs

  • Hooks

In this chapter, we will combine everything into one complete enterprise application.

Our case study is a Laundry Management System.

This chapter explains how every folder communicates with the others and how data flows through the application from the user interface to the database.

main.tsx → Render React → Load Providers → Load Router → Render App.tsx → Open Login Page or Dashboard

Login Page → Login Form → Validation → auth.service.ts → auth.api.ts → Axios → POST /login → Spring Boot → JWT Token → LocalStorage → AuthContext → Dashboard

Each order belongs to:

  • Customer
  • Laundry
  • Tailoring
  • Payment

Architecture:

OrdersPage → CreateOrderForm → Select Customer → Select Services → Calculate Total → order.service.ts → order.api.ts → POST /orders

Backend:

OrderController → OrderService → CustomerRepository → LaundryRepository → TailoringRepository → PaymentRepository → Database

Pending → Received → Washing → Drying → Ironing → Tailoring → Ready → Delivered

Services Communication

Services are the application's brain.

Example:

Customer Page → Customer Service → Validate Data → Transform Data → Call API → Return Result

Services should never render UI.

API Communication

API files are responsible only for HTTP communication.

Example:

  • customer.api.ts
  • ↓
  • GET
  • POST
  • PUT
  • DELETE

Nothing else.

Axios Communication

Axios automatically:

Add Base URL → Attach JWT → Serialize JSON → Send Request → Receive Response → Handle Errors → Return Data

All API files reuse the same Axios instance.

React Query Communication

React Query sits between Components and APIs.

Component → React Query → Service → API → Axios

Responsibilities:

  • Cache
  • Refetch
  • Retry
  • Synchronization
  • Loading State
  • Error State

Best Practices

  • Keep components focused on presentation.
  • Move business logic into services.
  • Keep API files limited to HTTP communication.
  • Reuse components whenever possible.
  • Use custom hooks to reduce duplication.
  • Use React Query for all server state.
  • Keep layouts independent from business logic.
  • Validate data before calling APIs.
  • Never mix UI logic with networking code.
  • Separate responsibilities between layers.

Common Mistakes

❌ Calling Axios directly inside every component.

❌ Placing business logic inside pages.

❌ Creating huge components with hundreds of lines.

❌ Duplicating API calls.

❌ Mixing authentication with UI code.

❌ Ignoring loading and error states.

❌ Passing props through many nested components instead of using Context when appropriate.

❌ Creating utility functions inside components instead of using the utils folder.

Chapter Summary

An enterprise React application is built using layers, where each layer has a single responsibility.

A user action flows from the UI through Components, Hooks, Services, APIs, Axios, and the Spring Boot backend before reaching the database. The response then travels back through the same layers until React updates only the necessary parts of the interface.

By understanding how these layers interact—and by respecting the separation of concerns—you can confidently read, maintain, and build large-scale React applications integrated with Spring Boot. Once you understand this journey—from the user's click to the database and back—you can confidently read, debug, extend, and build professional React applications integrated with Spring Boot or any modern backend.
