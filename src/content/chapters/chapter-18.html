State Management in React Applications

Introduction

State management is one of the most important concepts in React.

Every React application needs to remember information while the user interacts with it.

Examples:

  • Current user
  • Shopping cart items
  • Selected language
  • Theme preference
  • Form values
  • Notifications
  • Table filters
  • Server data

This information is called State.

Understanding state management is essential for building professional React applications.

What is State?

State is data that can change over time and affects the user interface.

Example:

const [count, setCount] = useState(0);

Current state:

count = 0

After clicking:

count = 1

React updates the UI automatically.

State vs Normal Variables

Normal variable:

let count = 0;

count++;

React does not know that the value changed.

The UI will not update.

State:

const [count, setCount] = useState(0);

setCount(count + 1);

React knows:

State Changed → Re-render Component → Update UI

Types of State in React

Modern applications usually have several types of state.

  • Application State
  • Server State
  • Component State
  • URL State
  • Form State

Component State

State that belongs to one component.

Example:

function Button(){

const [loading,setLoading] = useState(false);

}

Used for:

  • Modals
  • Toggles
  • Inputs
  • Local UI changes

Props Drilling Problem

Passing data through many components:

App → Layout → Page → Component → Child → Button

Example:

<Component user={user}/>

After many levels:

<Button user={user}/>

This becomes difficult to maintain.

Context API

React provides Context API to share global data.

Example:

AuthContext → User Information → Available Everywhere

Context Example

{
 user,

Use:

Common Contexts

Enterprise applications usually have:

  • AuthContext
  • ThemeContext
  • LanguageContext
  • NotificationContext

Context Limitations

Context is useful, but it is not a complete state management solution.

Problems:

  • Large contexts cause re-renders
  • Harder debugging
  • Complex updates become difficult

For large applications, external state libraries are often used.

Server State vs Client State

This is one of the most important concepts.

Client State

Data that belongs to the frontend.

Examples:

  • Sidebar Open
  • Theme
  • Modal Visible
  • Selected Tab

Managed by:

  • useState
  • Context
  • Zustand
  • Redux

Server State

Data that comes from backend.

Examples:

  • Customers
  • Orders
  • Employees
  • Reports

Managed by:

  • React Query
  • SWR
  • Apollo Client

Why Server State is Different

Server data has:

  • Loading
  • Errors
  • Cache
  • Synchronization
  • Refreshing

Example:

Customers Table → Backend Changes → Frontend Should Update

React Query handles this automatically.

React Query State Management

Example:

const {
data,
isLoading,
error
}=useQuery({
queryKey:["customers"],
queryFn:getCustomers
});

React Query manages:

  • Data
  • Loading
  • Error
  • Cache
  • Refetch

Redux

Redux is a popular state management library.

Architecture:

Component → Action → Reducer → Store → Component

Redux Store

The store contains global state.

Example:

Store
│
├── auth
├── cart
├── settings
└── notifications

Redux Actions

Actions describe what happened.

Example:

{
 type:"LOGIN",
 payload:user
}

Reducers

Reducers decide how state changes.

Example:

function authReducer(state,action){

switch(action.type){

case "LOGIN":

return action.payload;

}

}

Redux Toolkit

Modern Redux uses Redux Toolkit.

It simplifies:

  • Store creation
  • Reducers
  • Actions
  • Async logic

Redux Architecture

Example:

Login Button → Dispatch LOGIN Action → Auth Slice → Update Store → Components Re-render

URL State

Sometimes state belongs in the URL.

Example:

/customers?page=2&search=john

Benefits:

  • Shareable links
  • Browser history support
  • Refresh keeps state

Used for:

  • Search
  • Pagination
  • Filters

Local Storage State

Some data should survive browser refresh.

Examples:

  • Language
  • User Preferences

Example:

"dark"

Session Storage

Similar to localStorage.

Difference:

localStorage → Permanent → sessionStorage → Removed after browser closes

Choosing the Right Tool

Use:

useState

For:

  • Small local changes
  • Modal state
  • Inputs

Context API

For:

  • Authentication
  • Theme
  • Language

React Query

For:

  • API data
  • Backend communication
  • Caching

Redux Toolkit

For:

  • Very large applications
  • Complex global state
  • Multiple teams

Zustand

For:

  • Medium applications
  • Simple global state

Common State Management Mistakes

❌ Putting everything in Redux.

❌ Using Context for huge frequently changing data.

❌ Storing server data manually in state.

❌ Duplicating the same state in multiple places.

❌ Passing props through many levels.

❌ Keeping unnecessary global state.

❌ Forgetting to reset state.

State Management Best Practices

✅ Keep state as close as possible to where it is used.

✅ Separate client state from server state.

✅ Use React Query for backend data.

✅ Use Context for simple global values.

✅ Use Redux/Zustand only when needed.

✅ Avoid unnecessary global state.

✅ Normalize complex data structures.

✅ Keep state predictable.

Chapter Summary

State management is the foundation of interactive React applications.

Professional React applications usually divide state into different categories:

  • Component State for local UI behavior.
  • Context State for simple global information.
  • Server State managed by React Query.
  • Global Client State managed by Redux Toolkit or Zustand.
  • Form State managed by React Hook Form.
  • URL State for shareable navigation data.

The goal is not to use the biggest state management library.

The goal is to choose the correct tool for each type of data.

A well-designed state architecture makes React applications easier to understand, faster, and more scalable.
