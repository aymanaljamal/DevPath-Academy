10.1 Introduction to TypeScript

Simple Explanation

TypeScript is a superset of JavaScript that adds static typing. It helps you catch errors early, write more predictable code, and get better editor support. Think of it as JavaScript with superpowers - you write JavaScript, but with type annotations that help prevent bugs.

Think of TypeScript like a spell-checker for your code. Just as a spell-checker catches spelling errors before you send an email, TypeScript catches type errors before you run your code.

Technical Explanation

TypeScript is a strongly typed programming language that builds on JavaScript. It adds optional static types, classes, interfaces, and other features to JavaScript. TypeScript code is transpiled to plain JavaScript that runs anywhere JavaScript runs.

Key characteristics: - Static Typing: Catch errors at compile time - Type Inference: TypeScript can infer types automatically - Structural Typing: Types are checked by their structure - Generics: Write reusable, type-safe code - ES Features: Support for latest ECMAScript features - Tooling: Excellent IDE support with autocomplete and refactoring

Professional Explanation

In enterprise React development, TypeScript is essential for: - Code Quality: Catch type errors before runtime - Maintainability: Types serve as documentation - Refactoring: Safe refactoring with type checking - Collaboration: Clear contracts between components - IDE Support: Better autocomplete and error detection - Scalability: Types help manage growing codebases

10.3 Basic Types

Simple Explanation

Basic types in TypeScript are the building blocks of type annotations. They include primitive types like string, number, boolean, and more complex types like arrays and objects.

Technical Explanation

TypeScript has several basic types: - Primitive Types: string, number, boolean, null, undefined, symbol, bigint - Any: Disables type checking (avoid using) - Void: No return value - Never: Function that never returns - Unknown: Type-safe alternative to any - Arrays: type[] or Array<type> - Tuples: Fixed-length arrays - Enums: Named constants

Professional Explanation

In React TypeScript, basic types are used for: - Props: Define component prop types - State: Type state variables - Functions: Type parameters and return values - API Responses: Type API data - Event Handlers: Type event objects

10.4 Interfaces and Type Aliases

Simple Explanation

Interfaces and type aliases are ways to define custom types. They describe the shape of an object or the structure of a type. Interfaces are more commonly used for object types, while type aliases can be used for any type.

Think of interfaces like contracts that define what properties and methods an object must have.

Technical Explanation

Interfaces: Define contracts for object structures - Can be extended - Can be implemented by classes - Can be merged (declaration merging) - Better for object types

Type Aliases: Create new names for types - Can represent any type (primitives, unions, intersections) - Cannot be extended - No declaration merging - More flexible for complex types

Professional Explanation

Best practices: - Use interfaces for public API definitions - Use type aliases for union types, tuple types, and type aliases - Use interfaces when you need inheritance - Use type aliases for function signatures - Document interfaces with JSDoc

10.5 Generics

Simple Explanation

Generics allow you to create reusable components and functions that work with multiple types. They're like type variables that you can specify when using the component or function.

Think of generics like a template for a stamp - you can use the same stamp with different colored ink (types) to stamp different designs.

Technical Explanation

Generics allow you to write code that works with a variety of types rather than a single one. The type is specified when the function or component is used.

Key concepts: - Type Parameters: Placeholders for types - Constraints: Restrict type parameters - Default Types: Default type if not specified - Generic Components: Reusable React components - Generic Hooks: Reusable hooks with generic types

Professional Explanation

Generics are essential for: - Data Structures: Reusable collections - API Clients: Type-safe API responses - Form Hooks: Type-safe form handling - Component Libraries: Flexible, type-safe components - Utility Functions: Reusable type-safe utilities

Generics Examples

// Basic generic function
function identity<T>(value: T): T {
    return value;
}

const num = identity<number>(42); // Type: number
const str = identity<string>("Hello"); // Type: string
const inferred = identity("Hello"); // Type inferred as string

// Generic with multiple type parameters
function pair<T, U>(first: T, second: U): [T, U] {
    return [first, second];
}

const result = pair("Hello", 42); // Type: [string, number]

// Generic with constraints
interface HasLength {
    length: number;
}

function logLength<T extends HasLength>(item: T): T {
    console.log(item.length);
    return item;
}

logLength("Hello"); // Works
logLength([1, 2, 3]); // Works
// logLength(42); // Error: number doesn't have length

// Generic custom hook
function useApi<T>(url: string) {
    const [data, setData] = useState<T | null>(null);
    const [loading, setLoading] = useState(true);
    const [error, setError] = useState<string | null>(null);

    useEffect(() => {
        const fetchData = async () => {
            try {
                const response = await fetch(url);
                const json = await response.json();
                setData(json);
            } catch (err) {
                setError(err instanceof Error ? err.message : 'An error occurred');
            } finally {
                setLoading(false);
            }
        };

        fetchData();
    }, [url]);

    return { data, loading, error };
}

// Using generic hook
function UserPage() {
    const { data: user, loading, error } = useApi<User>('/api/users/1');

    if (loading) return <div>Loading...</div>;
    if (error) return <div>Error: {error}</div>;
    if (!user) return <div>User not found</div>;

    return (
        <div>
            <h2>{user.name}</h2>
            <p>{user.email}</p>
        </div>
    );
}

// Generic with default type
function createArray<T = string>(length: number, value: T): T[] {
    return Array(length).fill(value);
}

const strings = createArray(3, "Hello"); // Type: string[]
const numbers = createArray(3, 42); // Type: number[] (inferred)

// Generic with extends and keyof
function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
    return obj[key];
}

const user = { name: "John", age: 30, email: "john@example.com" };
const name = getProperty(user, "name"); // Type: string
const age = getProperty(user, "age"); // Type: number
// const invalid = getProperty(user, "invalid"); // Error: invalid key

10.6 Utility Types

Simple Explanation

Utility types are built-in TypeScript types that help you transform existing types. They allow you to create new types based on existing ones without rewriting them.

Think of utility types like tools in a workshop - each tool (utility type) helps you shape and transform your materials (types) in a specific way.

Technical Explanation

TypeScript provides several built-in utility types: - Partial: Makes all properties optional - Required: Makes all properties required - Readonly: Makes all properties readonly - Pick: Select specific properties - Omit: Remove specific properties - Exclude: Exclude types - Extract: Extract types - Record: Create object type with keys - ReturnType: Get function return type - Parameters: Get function parameters

Professional Examples

Utility types are essential for: - Form Handling: Partial for form values - API Clients: Pick for selecting fields - Type Safety: Readonly for immutable data - Data Transformation: Omit for sensitive data - Type Mapping: Record for dictionaries

10.7 Type Narrowing and Type Guards

Simple Explanation

Type narrowing is the process of refining a variable's type from a broader type to a more specific one. Type guards are conditions that help TypeScript narrow down types.

Think of type narrowing like a detective investigation - you start with a suspect (unknown type) and gather clues (conditions) until you can identify exactly who they are (specific type).

Technical Explanation

Type narrowing helps TypeScript understand more specific types: - typeof: Check primitive types - instanceof: Check class instances - in: Check property existence - Equality: Check equality with specific values - User-defined: Custom type guard functions

Type guards are functions that return a type predicate, helping TypeScript narrow types.

Professional Explanation

Type narrowing is essential for: - API Responses: Handling different response shapes - Form Inputs: Validating user input - Error Handling: Different error types - Event Handling: Different event types - Polymorphism: Handling different types

Type Narrowing and Type Guards Examples

// typeof type guard
function processValue(value: string | number | boolean) {
    if (typeof value === 'string') {
        // value is string
        return value.toUpperCase();
    }

    if (typeof value === 'number') {
        // value is number
        return value.toFixed(2);
    }

    // value is boolean
    return value ? 'true' : 'false';
}

// instanceof type guard
class Dog {
    bark() {
        console.log('Woof!');
    }
}

class Cat {
    meow() {
        console.log('Meow!');
    }
}

function makeSound(animal: Dog | Cat) {
    if (animal instanceof Dog) {
        animal.bark(); // Dog
    } else {
        animal.meow(); // Cat
    }
}

// in operator type guard
interface Car {
    drive(): void;
    fuel: string;
}

interface Boat {
    sail(): void;
    fuel: string;
}

function operate(vehicle: Car | Boat) {
    if ('drive' in vehicle) {
        vehicle.drive(); // Car
    } else {
        vehicle.sail(); // Boat
    }
}

// Equality narrowing
function processStatus(status: 'success' | 'error' | 'loading') {
    if (status === 'success') {
        // Handle success
        return 'Operation completed successfully';
    }

    if (status === 'error') {
        // Handle error
        return 'Operation failed';
    }

    // status is 'loading'
    return 'Operation in progress...';
}

// User-defined type guard
interface AdminUser {
    id: number;
    name: string;
    role: 'admin';
    permissions: string[];
}

interface RegularUser {
    id: number;
    name: string;
    role: 'user';
    preferences: {
        theme: 'light' | 'dark';
        notifications: boolean;
    };
}

function isAdmin(user: AdminUser | RegularUser): user is AdminUser {
    return user.role === 'admin';
}

function isRegularUser(user: AdminUser | RegularUser): user is RegularUser {
    return user.role === 'user';
}

function getUserInfo(user: AdminUser | RegularUser) {
    if (isAdmin(user)) {
        // user is AdminUser
        return `Admin with permissions: ${user.permissions.join(', ')}`;
    }

    if (isRegularUser(user)) {
        // user is RegularUser
        return `User with theme: ${user.preferences.theme}`;
    }

    return 'Unknown user type';
}

// Type guard with discriminated union
type Shape =
    | { kind: 'circle'; radius: number }
    | { kind: 'rectangle'; width: number; height: number }
    | { kind: 'triangle'; base: number; height: number };

function getArea(shape: Shape): number {
    switch (shape.kind) {
        case 'circle':
            return Math.PI * shape.radius ** 2;
        case 'rectangle':
            return shape.width * shape.height;
        case 'triangle':
            return (shape.base * shape.height) / 2;
        default:
            throw new Error('Unknown shape');
    }
}

// Type guard with null checks
function processString(value: string | null | undefined): string {
    if (value === null || value === undefined) {
        return 'No value provided';
    }

    // value is string
    return value.toUpperCase();
}

// Custom type guard with async
async function isUserValid(user: unknown): Promise<user is User> {
    if (!user || typeof user !== 'object') {
        return false;
    }

    const possibleUser = user as User;
    return typeof possibleUser.id === 'number' &&
           typeof possibleUser.name === 'string' &&
           typeof possibleUser.email === 'string';
}

    status: 'success';
}

function isApiError(response: unknown): response is ApiError {
    return (
        typeof response === 'object' &&
        response !== null &&
        'code' in response &&
        'message' in response
    );
}

function DataFetcher() {
    const [data, setData] = useState<unknown>(null);
    const [loading, setLoading] = useState(true);
    const [error, setError] = useState<string | null>(null);

    useEffect(() => {
        fetch('/api/data')
            .then(res => res.json())
            .then((response) => {
                if (isApiError(response)) {
                    setError(response.message);
                } else {
                    setData(response);
                }
            })
            .catch((err) => {
                setError(err.message);
            })
            .finally(() => {
                setLoading(false);
            });
    }, []);

    if (loading) return <div>Loading...</div>;
    if (error) return <div>Error: {error}</div>;

    return <div>{JSON.stringify(data)}</div>;
}

Simple Explanation

Advanced types in TypeScript allow you to create complex, flexible type definitions. They include mapped types, conditional types, template literal types, and other powerful type-level programming features.

Advanced types include: - Mapped Types: Transform properties of a type - Conditional Types: Types based on conditions - Template Literal Types: String manipulation at type level - Infer: Extract types from complex types - Indexed Access Types: Access property types - Recursive Types: Self-referential types

Professional Explanation

Advanced types are useful for: - Type Libraries: Creating reusable type utilities - API Clients: Type-safe API responses - Form Libraries: Type-safe form handling - State Management: Type-safe state updates - Component Libraries: Flexible, type-safe components

Advanced Types Examples

// Mapped types
type Readonly<T> = {
    readonly [P in keyof T]: T[P];
};

type Partial<T> = {
    [P in keyof T]?: T[P];
};

type Nullable<T> = {
    [P in keyof T]: T[P] | null;
};

type MyUser = {
    id: number;
    name: string;
    email: string;
    age: number;
};

type ReadonlyUser = Readonly<MyUser>;
type PartialUser = Partial<MyUser>;
type NullableUser = Nullable<MyUser>;

// Conditional types
type IsString<T> = T extends string ? true : false;
type IsNumber<T> = T extends number ? true : false;

type StringCheck = IsString<'hello'>; // true
type NumberCheck = IsNumber<'hello'>; // false

// Template literal types
type EventType = 'click' | 'hover' | 'focus';
type EventHandler = `on${Capitalize<EventType>}`;
// 'onClick' | 'onHover' | 'onFocus'

type Color = 'red' | 'blue' | 'green';
type Size = 'small' | 'medium' | 'large';
type ColorSize = `${Color}-${Size}`;
// 'red-small' | 'red-medium' | 'red-large' | 'blue-small' | ...

// Infer keyword
type ReturnType<T> = T extends (...args: any[]) => infer R ? R : never;

function greet(name: string): string {
    return `Hello, ${name}!`;
}

type GreetReturn = ReturnType<typeof greet>; // string

// Indexed access types
type UserName = MyUser['name']; // string
type UserAge = MyUser['age']; // number
type UserKeys = keyof MyUser; // 'id' | 'name' | 'email' | 'age'

// Recursive types

    [key: string]: JsonValue;
}
interface JsonArray extends Array<JsonValue> {}

// Mapped type with modifiers

    -readonly [P in keyof T]: T[P];
};

    [P in keyof T]-?: T[P];
};

// Conditional mapped types
type ExtractProperty<T, U> = {
    [P in keyof T]: T[P] extends U ? P : never;
}[keyof T];

// Union transformation types
type UnionToIntersection<U> =
    (U extends any ? (k: U) => void : never) extends ((k: infer I) => void) ? I : never;

type Union = { a: number } | { b: string } | { c: boolean };
type Intersection = UnionToIntersection<Union>; // { a: number } & { b: string } & { c: boolean }

// Advanced React type definitions
type ComponentProps<T> = T extends React.ComponentType<infer P> ? P : never;

function withAuth<T extends React.ComponentType<any>>(
    Component: T

    };
}

// Type-safe event system
type EventMap = {
    userCreated: { id: number; name: string };
    userDeleted: { id: number };
    userUpdated: { id: number; changes: Partial<User> };
};

type EventListener<T> = (data: T) => void;

class EventBus {
    private listeners: {
        [K in keyof EventMap]?: EventListener<EventMap[K]>[];
    } = {};

    emit<K extends keyof EventMap>(event: K, data: EventMap[K]) {
        const listeners = this.listeners[event] || [];
        listeners.forEach(listener => listener(data));
    }

    on<K extends keyof EventMap>(event: K, listener: EventListener<EventMap[K]>) {
        if (!this.listeners[event]) {
            this.listeners[event] = [];
        }
        this.listeners[event]!.push(listener);
        return () => this.off(event, listener);
    }

    off<K extends keyof EventMap>(event: K, listener: EventListener<EventMap[K]>) {
        const listeners = this.listeners[event];
        if (listeners) {
            this.listeners[event] = listeners.filter(l => l !== listener);
        }
    }
}

// Using the event system
const eventBus = new EventBus();

eventBus.on('userCreated', (data) => {
    console.log('User created:', data.id, data.name);
});

eventBus.emit('userCreated', { id: 1, name: 'John' });

function List<T>({

// Component with context
interface ThemeContextValue {
    theme: 'light' | 'dark';
    toggleTheme: () => void;
}

const ThemeContext = React.createContext<ThemeContextValue | null>(null);

function ThemeProvider({ children }: { children: React.ReactNode }) {
    const [theme, setTheme] = useState<'light' | 'dark'>('light');

    const toggleTheme = () => {
        setTheme(prev => prev === 'light' ? 'dark' : 'light');
    };

    const value: ThemeContextValue = {
        theme,
        toggleTheme
    };

    return (
        <ThemeContext.Provider value={value}>
            {children}
        </ThemeContext.Provider>
    );
}

function useTheme() {
    const context = useContext(ThemeContext);
    if (!context) {
        throw new Error('useTheme must be used within a ThemeProvider');
    }
    return context;
}

function ThemedButton() {

        </button>
    );
}

// Custom hook with types
function useFetch<T>(url: string): {
    data: T | null;
    loading: boolean;
    error: string | null;
    refetch: () => void;
} {
    const [data, setData] = useState<T | null>(null);
    const [loading, setLoading] = useState(true);
    const [error, setError] = useState<string | null>(null);

    const fetchData = useCallback(async () => {
        setLoading(true);
        setError(null);
        try {
            const response = await fetch(url);
            const json = await response.json();
            setData(json);
        } catch (err) {
            setError(err instanceof Error ? err.message : 'An error occurred');
        } finally {
            setLoading(false);
        }
    }, [url]);

    useEffect(() => {
        fetchData();
    }, [fetchData]);

    return { data, loading, error, refetch: fetchData };
}

function UserProfile() {

    if (!user) return <div>User not found</div>;

    return (
        <div>
            <h2>{user.name}</h2>
            <p>{user.email}</p>
            {user.age && <p>Age: {user.age}</p>}
        </div>
    );
}

10.10 Common Mistakes and Best Practices

10.10.1 Common Mistakes

// ❌ Using any instead of proper types
function processData(data: any) {
    // Disables type checking
    return data.name;
}

// ✅ Use proper types
function processData(data: { name: string }) {
    return data.name;
}

// ❌ Not handling optional props
interface User {
    id: number;
    name: string;
    email?: string;
}

function UserCard({ user }: { user: User }) {
    return (
        <div>
            <h2>{user.name}</h2>
            <p>{user.email}</p> {/* ❌ email might be undefined */}
        </div>
    );
}

// ✅ Handle optional props
function UserCard({ user }: { user: User }) {
    return (
        <div>
            <h2>{user.name}</h2>
            <p>{user.email || 'No email provided'}</p>
        </div>
    );
}

// ❌ Type assertion abuse
const user = {} as User;
user.id = 1; // ❌ Not safe

// ✅ Use proper initialization
const user: User = {
    id: 1,
    name: 'John'
};

// ❌ Overly complex types
interface ComplexType {
    data: {
        items: {
            id: number;

                created: string;

 * User information interface
 * @property id - Unique user identifier
 * @property name - Full name of the user

    email: string;
