17

React Security Best Practices

Introduction

Security is one of the most important parts of modern web development.

A React application is not only a user interface. It communicates with:

  • Backend APIs
  • Databases
  • Authentication systems
  • File storage
  • Third-party services

A security mistake in the frontend can expose:

  • User information
  • Authentication tokens
  • Business data
  • Application functionality

Professional React developers must understand common security risks and how to protect applications.

The Security Model of a React Application

A React application usually follows this architecture:

User Browser → React Application → HTTPS Request → Spring Boot Backend → Database

Important rule:

The frontend is never trusted.

Everything important must be verified by the backend.

Frontend Security vs Backend Security

Frontend Security

Responsible for:

  • User experience
  • Hiding unavailable UI
  • Input validation
  • Preventing accidental mistakes

Examples:

  • Disable button
  • Show error message
  • Validate form

Backend Security

Responsible for:

  • Real authorization
  • Data protection
  • Permissions
  • Authentication
  • Business rules

Example:

Even if a user modifies JavaScript:

isAdmin = true

The backend must reject unauthorized requests.

Authentication vs Authorization

These concepts are different.

Authentication

Authentication answers:

Who are you?

Example:

Username + Password → JWT Token → User Logged In

Authorization

Authorization answers:

What are you allowed to do?

Example:

  • Admin
  • Can delete users
  • Employee
  • Cannot delete users

JWT Authentication Flow

Modern React + Spring Boot applications commonly use JWT.

Flow:

User → Login Form → auth.api.ts → POST /login → Spring Security → Generate JWT → Return Token → React Stores Token → Future Requests Include Token → Backend Validates Token

JWT Structure

A JWT contains three parts:

Header.Payload.Signature

Example:

xxxxx.yyyyy.zzzzz

Header

Contains information about the token.

Example:

{
"type":"JWT",
"algorithm":"HS256"
}

Payload

Contains user information.

Example:

{
"id":10,
"role":"ADMIN"
}

Important:

The payload is encoded, not encrypted.

Do not store secrets inside JWT.

Signature

Used to verify that the token was not modified.

Where Should We Store JWT?

Common options:

localStorage

Example:

localStorage.setItem(
"token",
jwt
);

Advantages:

  • Simple
  • Easy access

Disadvantages:

  • Vulnerable to XSS attacks

Cookies

HttpOnly Secure Cookies are often safer.

Advantages:

  • JavaScript cannot access token
  • Better protection against XSS

Disadvantages:

  • Requires CSRF protection

Enterprise Recommendation

For sensitive applications:

  • HttpOnly Cookie
  • +
  • Secure Flag
  • +
  • SameSite Policy

is usually preferred.

Axios Interceptors

Axios interceptors automatically attach tokens.

Example:

Request → Axios Interceptor → Add Authorization Header → Backend

Header:

  • Authorization:
  • Bearer TOKEN

Protected Routes

React can protect pages visually.

Example:

  • Dashboard
  • ↓
  • Check User
  • ↓
  • Logged In?
  • Yes → Show Page
  • No → Login

Example:

<ProtectedRoute>

<Dashboard />

</ProtectedRoute>

Important Security Rule

Protected routes in React are NOT real security.

Why?

Because users can modify frontend code.

Real protection:

  • React Protection
  • +
  • Spring Security Authorization

Role-Based Access Control (RBAC)

Applications usually have roles.

Example:

  • ADMIN
  • MANAGER
  • EMPLOYEE
  • CUSTOMER

Permission Example

  • ADMIN
  • ✓ Create Employee
  • ✓ Delete Customer
  • ✓ View Reports
  • EMPLOYEE
  • ✓ Update Order Status
  • ✗ Delete Customer

XSS Attack

Cross-Site Scripting

XSS happens when attackers inject malicious JavaScript.

Example:

User enters:

<script>
alert("Hacked")
</script>

If displayed incorrectly:

Browser Executes Script

React Protection Against XSS

React escapes content automatically.

Example:

<div>

{username}

</div>

React converts:

<script>

into safe text.

Dangerous HTML

Avoid:

dangerouslySetInnerHTML

Example:

<div
dangerouslySetInnerHTML={{
__html:data
}}
/>

This bypasses React protection.

Only use with trusted content.

Sanitization

If HTML must be displayed:

Use sanitizers.

Example:

User Input → Sanitize → Safe HTML → Display

Libraries:

  • DOMPurify

CSRF Attack

Cross-Site Request Forgery

An attacker tricks a logged-in user into sending unwanted requests.

Example:

User is logged in.

Attacker creates:

Fake Website → Send Delete Request → User Account

CSRF Protection

Solutions:

  • SameSite Cookies
  • CSRF Tokens
  • Backend Validation

SQL Injection

This happens on the backend.

Example:

Bad query:

SELECT *
FROM users
WHERE name='input'

Attack:

' OR 1=1

Protection:

  • Prepared Statements
  • JPA
  • Hibernate
  • Validation

React Responsibility

React should:

  • Validate input
  • Avoid unsafe HTML
  • Send correct data

Backend must:

  • Validate again
  • Protect database

Input Validation

Never trust user input.

Examples:

Email:

test@gmail.com

Password:

Minimum 8 characters

Phone:

Correct format

Validation Layers

Professional applications validate at multiple levels.

React Validation → API Validation → Spring Validation → Database Constraints

File Upload Security

File uploads are dangerous.

Attack examples:

  • Malicious files
  • Huge files
  • Wrong file types

Safe Upload Process

User Selects File → Check Size → Check Extension → Check MIME Type → Upload → Store Securely

Example Restrictions

Images:

Allowed:

  • jpg
  • png
  • webp

Maximum:

5 MB

Environment Security

Never expose:

  • DATABASE_PASSWORD
  • SECRET_KEY
  • PRIVATE_API_KEY

inside React.

Bad:

VITE_SECRET_PASSWORD=123

Anyone can see it.

HTTPS

Production applications must use HTTPS.

Without HTTPS:

Browser → Network → Attacker Can Read Data

With HTTPS:

Encrypted Connection

Content Security Policy (CSP)

CSP controls what resources the browser can load.

Example:

Allow:

  • Company Domain
  • Trusted CDN

Block:

Unknown Scripts

Security Headers

Important headers:

  • Content-Security-Policy
  • X-Frame-Options
  • X-Content-Type-Options
  • Strict-Transport-Security

Usually configured in Nginx or backend.

Dependency Security

React projects use many packages.

Example:

npm install package

A package may contain vulnerabilities.

Check:

npm audit

Fix:

npm audit fix

Keeping Dependencies Updated

Old packages may contain:

  • Security vulnerabilities
  • Bugs
  • Performance issues

Regular updates are important.

Error Handling Security

Never expose internal errors.

Bad:

  • Database connection failed:
  • password=123456

Good:

Something went wrong.
Please try again.

Logging Security

Never log:

  • Passwords
  • Tokens
  • Credit cards
  • Private information

Bad:

console.log(userToken);

Security Checklist

Before production:

✅ Use HTTPS

✅ Validate user input

✅ Protect routes

✅ Use backend authorization

✅ Avoid dangerous HTML rendering

✅ Protect JWT tokens

✅ Secure file uploads

✅ Remove sensitive logs

✅ Audit dependencies

✅ Configure security headers

✅ Keep packages updated

Enterprise Security Flow

User → React Application → Input Validation → HTTPS → Axios → JWT Authentication → Spring Security → Authorization Check → Business Logic → Database → Response → Safe UI Update

Common Security Mistakes

❌ Trusting frontend permissions.

❌ Storing secrets in React.

❌ Using localStorage without understanding risks.

❌ Using dangerouslySetInnerHTML with user data.

❌ Skipping backend validation.

❌ Uploading files without restrictions.

❌ Exposing error details.

❌ Ignoring dependency vulnerabilities.

❌ Using HTTP in production.

Chapter Summary

Security in React applications is based on one main principle:

Never trust the client.

React is responsible for creating a secure user experience, but the backend is responsible for enforcing security.

A professional React application should combine:

  • Secure authentication
  • Proper authorization
  • Safe data handling
  • Input validation
  • HTTPS
  • Secure token management
  • Dependency monitoring
  • Protected backend APIs

When React and Spring Boot security practices work together, the application becomes safer, more reliable, and ready for enterprise production environments. Understanding deployment and DevOps practices is essential for building enterprise-grade React applications that are reliable, scalable, and maintainable.
