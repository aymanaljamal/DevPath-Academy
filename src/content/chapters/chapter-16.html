Deployment and DevOps for React Applications

Introduction

Building a React application is only the first step.

A completed application must eventually be deployed so that users can access it over the Internet.

This chapter explains how professional React applications move from a developer's computer to production servers using modern deployment techniques.

By the end of this chapter, you will understand:

  • Development vs Production
  • Vite Build Process
  • Environment Variables
  • Static Hosting
  • Reverse Proxy
  • Docker
  • Docker Compose
  • CI/CD
  • GitHub Actions
  • Nginx
  • Production Best Practices

What is Deployment?

Deployment is the process of making an application available to users.

Development Environment

Developer Computer → localhost:5173

Production Environment

Internet → https://mycompany.com

Instead of running on your computer, the application runs on a production server.

Development vs Production

Development

Characteristics:

  • Fast Refresh
  • Source Maps
  • Error Overlay
  • Debugging
  • Development Server

Command

npm run dev

Example

http://localhost:5173

Production

Characteristics

  • Minified JavaScript
  • Optimized CSS
  • Compressed Assets
  • Tree Shaking
  • Fast Loading

Command

npm run build

Result

dist/

The dist folder is the application that gets deployed.

How Vite Works

When you run:

npm run dev

Vite starts a development server.

Browser → Vite Dev Server → Source Files

No production build is created.

When you run:

npm run build

Flow:

TypeScript → Compile → Bundle → Optimize → Minify → Generate dist/

The Build Process

Example project

src/ → Vite → Rollup → Optimization → dist/

The output may look like:

dist
│
├── assets
├── index.html
├── logo.svg
└── favicon.ico

Everything inside dist is production-ready.

What Happens During Build?

Vite performs many optimizations.

Minification

Before

function calculatePrice(price) {

    return price * 0.16;

}

After

function a(b){return.16*b}

Smaller files download faster.

Tree Shaking

Unused code is removed.

Example

Imported:

100 Functions

5 Functions

Output:

Only 5 Functions

Code Splitting

Instead of

  • app.js
  • 15 MB

React generates

  • login.js
  • dashboard.js
  • customers.js
  • orders.js

Each page loads independently.

Asset Optimization

Images

Fonts

CSS

JavaScript

All optimized for production.

Environment Variables

Applications should never hardcode:

  • API URLs
  • Secrets
  • API Keys
  • Tokens

Instead use environment variables.

Example:

VITE_API_URL=http://localhost:8080

Access inside React:

const url = import.meta.env.VITE_API_URL;

Common Environment Files

  • .env
  • .env.local
  • .env.development
  • .env.production

.env

Shared variables.

Example

VITE_APP_NAME=Laundry Management

.env.development

Development only.

Example

VITE_API_URL=http://localhost:8080

.env.production

Production only.

Example

VITE_API_URL=https://api.company.com

.env.local

Personal settings.

Ignored by Git.

Useful for:

  • Local API URLs
  • Personal tokens
  • Developer-specific configuration

Never Store Secrets

Bad

DATABASE_PASSWORD=123456

React runs in the browser.

Users can inspect JavaScript.

Frontend secrets are not secret.

Only public values belong in React environment variables.

Static Hosting

React produces static files.

Meaning:

  • HTML
  • CSS
  • JavaScript

These files can be served by:

  • Nginx
  • Apache
  • GitHub Pages
  • Netlify
  • Vercel
  • Firebase Hosting

Nginx

Nginx is a web server.

Architecture

Browser → Nginx → React Files

Nginx serves the generated dist folder.

Why Use Nginx?

Advantages

  • Very fast
  • Lightweight
  • HTTPS support
  • Compression
  • Reverse Proxy
  • Static file serving
  • Load balancing

Reverse Proxy

React

https://company.com

Backend

http://localhost:8080

Instead of exposing Spring Boot directly:

Browser → Nginx → Spring Boot

Benefits:

  • Security
  • SSL termination
  • Centralized routing
  • Better performance

Docker

Docker packages an application with everything it needs.

Without Docker

Works On My Machine

Problem:

Different computers

Different Node versions

Different operating systems

Different dependencies

With Docker

  • Application
  • +
  • Node
  • +
  • Dependencies
  • +
  • Configuration
  • =
  • Container

Runs the same everywhere.

Dockerfile

Example structure

Project
│
├── Dockerfile
├── package.json
└── src

Dockerfile defines:

  • Base image
  • Install dependencies
  • Build application
  • Serve production files

Multi-Stage Docker Build

Professional projects use multiple stages.

Flow

Node Image → Install Packages → Build React → Generate dist/ → Copy dist → Nginx Image → Production Container

Smaller and faster images.

Docker Compose

Applications often have multiple services.

Example

  • React
  • Spring Boot
  • MySQL
  • Redis
  • Nginx

Docker Compose starts them together.

Architecture

Docker Compose
│
├── frontend
├── backend
├── mysql
├── redis
└── nginx

One command starts everything.

Deployment Pipeline

Professional deployment usually follows this workflow.

Developer → Git Commit → Git Push → GitHub → GitHub Actions → Build → Tests → Docker Image → Docker Registry → Production Server → Users

Everything is automated.

Continuous Integration (CI)

CI means every code change is automatically verified.

Example

Push Code → Install Dependencies → Run Tests → Build → Success

No manual verification required.

Continuous Deployment (CD)

CD automatically publishes successful builds.

Example

Build → Docker Image → Production → Application Updated

GitHub Actions

GitHub Actions automates workflows.

Example

Push → Workflow → Install Node → Install Packages → Run Tests → Build → Deploy

Typical GitHub Actions Workflow

Developer Pushes Code → Checkout Repository → Setup Node.js → Install Dependencies → Run ESLint → Run Tests → Build React → Create Docker Image → Push Docker Image → Deploy

Deployment Checklist

Before deployment:

✅ Run tests

✅ Remove console logs

✅ Build successfully

✅ Verify environment variables

✅ Optimize images

✅ Check API URLs

✅ Enable HTTPS

✅ Configure caching

✅ Enable compression

✅ Verify routing

Common Deployment Mistakes

❌ Hardcoding API URLs.

❌ Committing .env.local.

❌ Storing secrets in frontend code.

❌ Deploying without tests.

❌ Ignoring HTTPS.

❌ Serving development builds.

❌ Forgetting SPA routing configuration in Nginx.

❌ Large unoptimized bundles.

❌ Missing caching headers.

Best Practices

✅ Use Vite for modern React applications.

✅ Keep development and production environments separate.

✅ Store configuration in environment variables.

✅ Never expose secrets in frontend code.

✅ Use Docker for consistent deployments.

✅ Serve React with Nginx in production.

✅ Automate builds using GitHub Actions.

✅ Run automated tests before deployment.

✅ Enable HTTPS and compression.

✅ Monitor production systems continuously.

Chapter Summary

Deployment transforms a React application from local development into a production-ready system accessible to users worldwide.

Modern React applications typically follow this lifecycle:

  1. Develop locally with Vite.
  2. Build optimized static files.
  3. Configure environment variables.
  4. Package the application with Docker.
  5. Serve it using Nginx.
  6. Automate testing and deployment with GitHub Actions.
  7. Monitor the application in production.
